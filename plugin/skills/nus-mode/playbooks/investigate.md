# Investigate

Investigate finds why a problem happens and the fix that removes its cause. Leave the project unchanged, with each reproduction and experiment outside it, and put the fix in the reply; since nothing changes, run it without asking the user first, apart from the approvals nus-mode asks for.

1. **Pin the problem down.** Write down what happens, what should happen and how to tell them apart, then reproduce it; where it shows only in another environment or only sometimes, gather each occurrence's record instead. Done when all three are written down, and a check outside the project shows the problem on demand or each occurrence's record shows it.
2. **Decompose it** into independent parts, each a question with its own evidence. Done when each part is a question that has its own evidence and can be answered without the others.
3. **Answer each part from evidence you observe,** and run a small experiment wherever one can confirm or refute an answer. Done when every part has an answer with the observed evidence it rests on, and each answer a small experiment could confirm or refute rests on one that was run outside the project.
4. **Find the cause.** Combine the answers into one account of why the problem happens, traced back to the earliest cause a change can remove. Done when the account explains every observation from steps 1 and 3 and reaches that cause.
5. **Find the fix that removes the cause.** Prefer a fix that makes the problem impossible, such as a type, a structure, a removed path or a check a tool enforces. Weigh each candidate by the [friction points](../SKILL.md#goal) it removes and adds and against [long term](../../principle-long-term/SKILL.md), and recommend one that removes more than it adds or, where none does, the one that leaves the fewest, and say so. Done when the candidates include a fix that makes the problem impossible or the reply says why none can; the reply holds each candidate with the friction points it removes and adds and how it fares against long term, and each rejected one with the reason it lost; the recommended fix removes the cause and more friction points than it adds or, where no candidate does, leaves the fewest, which the reply says; and the project is unchanged.

**Reply:** the problem, each part with its evidence, the cause, each candidate with the friction points it removes and adds and how it fares against long term, the recommended fix, each rejected candidate with its reason, why no candidate makes the problem impossible where none does, and, where no candidate removes more friction points than it adds, that none does.
