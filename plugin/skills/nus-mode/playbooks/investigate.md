# Investigate

Investigate finds why a problem happens, and the fix that removes its cause. Leave the project unchanged: keep each reproduction and experiment outside it, built to the full bar of [long term](../../principle-long-term/SKILL.md), and put the fix in the reply. Since it leaves the project unchanged, run its steps without asking the user first, whether or not you work on your own, apart from any action nus-mode has you ask approval for.

1. **Pin the problem down.** Write down what happens, what should happen, and how to tell them apart, then reproduce it. When it happens only in another environment, such as production, or only sometimes, gather each occurrence's record instead: logs, traces, metrics or reports. Done when what happens, what should happen and how to tell them apart are written down, and a check shows the problem on demand or each occurrence's record shows it; each reproduction sits outside the project, built to long term's full bar.
2. **Decompose it.** Split the problem into independent parts, each a question with its own evidence. Done when each part is stated as a question, has its own evidence, and can be answered without the others.
3. **Answer each part** from evidence you observe: running the code, or its runtime record, source or documentation. Where a small experiment can confirm or refute an answer, run one, such as a script, a minimal reproduction or a copy of the code with one change. Done when every part has an answer recorded with the observed evidence it rests on, and each answer a small experiment could confirm or refute rests on one that was run, outside the project and built to long term's full bar.
4. **Find the cause.** Combine the answers into one account of why the problem happens, traced back to the earliest cause a change can remove. Done when the account explains every observation from steps 1 and 3 and reaches the earliest cause a change can remove.
5. **Find the fix that removes the cause.** Prefer a change that makes the problem impossible, such as a type, a structure, a removed path or a check a tool enforces. Weigh each candidate by the [friction rate](../SKILL.md#goal) it would leave and against [long term](../../principle-long-term/SKILL.md), and recommend one that leaves fewer friction points than the code has now or, where none does, the one that leaves the fewest, and say so. Done when each candidate is recorded with the friction points it removes and adds and how it fares against long term; the recommended fix names the cause it removes and the friction points it removes and adds, and removes more than it adds or, where no candidate does, leaves the fewest friction points, which the reply says; each candidate that makes the problem impossible is the recommended fix or has the reason it lost; each other rejected candidate has the reason it lost; and the project is unchanged.

**Reply:** the problem, each part with its evidence, the cause, the recommended fix with the friction points it removes and adds, and every rejected candidate with its reason, and, where no candidate removes more friction points than it adds, that none does.
