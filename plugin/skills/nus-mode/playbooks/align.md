# Align

Align reshapes code to nus-mode's bar within its project's standards. It keeps what the code does for callers, names included: what callers can use, in no project what the user names, else each defined name reachable outside; each behaviour change a rule demands is a design decision, made once whoever decides agrees. Each change covers only its scope, departing from [long term](../../principle-long-term/SKILL.md)'s *finish what you touch* and *fix the flaw everywhere it appears* so it stays reviewable.

- **A snippet, file or named package** changes only itself, its tests and its process's entries. Step 2 counts only forms outside it, and its checks, step 3's tools at settings sparing each kept standard, pass but for its follow-ups' flaws. Refused behaviour changes, other changes to what callers can use, project-wide proposals, test layout and standards' homes become follow-ups. A file's or package's review agrees its named behaviour changes. A snippet returns in one reply block on the standard library and the snippet's imports, so it runs where it came from, unless the user agrees.
- **An input in no project** also takes the first bullet, this one winning where they differ, skipping step 3. Its checks are the formatter, linter and type checker [new project](new-project.md) picks, at the principles' strictest setting. Runs on inputs reaching each branch stand in for tests; its change goes in the reply.
- **A whole project that others decide**: send them step 3's proposals and step 4's plan in one message. A change waits for their agreement where it holds a proposal or their process asks first.

1. **Set the scope.** Record the input's kind, project, runtime (the lowest the project declares, else the user's answer, else the oldest [dependencies](../../principle-dependencies/SKILL.md) targets), each tracked file as authored, vendored or tool-generated, and who decides: the user for a snippet, else its maintainers where others share the project, else the user. Only authored files are counted or reshaped. Done when recorded: the kind, project, runtime, each file's status and who decides.
2. **Read the standards and run the baseline.** Read each agent instruction, doc, PR template, tool config, hook and CI file, recording where they disagree. Where nothing written decides, the form over half the instances that could differ keep is a standard, unless a principle's own rule, never a language skill's, makes it a flaw. Install the project, else the input's imports, on step 1's runtime, as its docs or CI do, run its checks and tests, restoring the tree after each. Done when recorded: each source read, each standard with its source, each disagreement, each check's and test's result and count, installed as its docs or CI do on step 1's runtime, and the tree restored.
3. **Settle the standards.** Propose:
   - nus-mode's form or rule for each standard it differs from;
   - one rule for each disagreement;
   - one command running every check, and commit hooks running it, where missing;
   - each missing part of [new project](new-project.md)'s `AGENTS.md`, the host files importing it and *Lay out the project*'s ignores;
   - given a remote, missing CI running that command, the GitHub settings new project configures and, given pull requests, a PR template;
   - for each other job lacking a tool, new project's pick.

   Set each tool at the principles' strictest setting that spares each kept standard. [Home](../../principle-dry/SKILL.md) each standard in its tool's config, else `AGENTS.md` or a guide it links. Done when recorded: each case a bullet names proposed, each proposal's and strictest setting's outcome or pending answer, each kept standard a proposal breaks at every setting, and each standard's home.
4. **Plan the changes.** List each flaw in scope against the settled standards, else nus-mode. Stage a project's changes: baseline failures; tooling and checks, with their tools' fixes, ignores, homes and, in the first, missing parts and settings; layout, with each check whose fixes move code; code; remaining tests and docs. A snippet, file or package is one change. A check exempts, until fixed, the flaws a later stage, follow-up or pending answer fixes. Each project change covers one stage over one area, or one check over its areas. A change that waits on another stacks on it. Done when recorded: each flaw assigned to one change or follow-up, each project change's stage, areas, base and exemptions, and any whole-project message sent.
5. **Make the plan's next change.** Before any hand or unsafe code fix, pin behaviour with a passing test. Run each check's tool over the scope in its own commit or reply line until rerunning changes nothing; hand-fix the rest. Create each file by its tool, else its format's documentation. Hold each commit to the baseline on step 1's runtime, and each check fixed or added to passing over the scope, failing on a planted break. Revise the plan, runtime and baseline as failures, answers or tools demand, resettling reopened standards by step 3. Done when recorded: its flaws fixed, each tool run's command, clean rerun and any commit or reply line, each created file's tool or format, each hand or unsafe fix's pin passing except named behaviour changes, each commit and check held, any hooks and CI running step 3's command, and each revision and resettled standard.
6. **Review, then open.** Review the change by new project's *Review your work*. Assign each flaw outside it to a later change or follow-up. Once it waits only on its review's answers, open each change outside the reply where the project takes pull requests, else push or commit its branch; then repeat steps 5–6. Done when each applying skill was reread, step 5's checks hold, the pass and cold read find only flaws so assigned, its runs of step 3's mutation tools, else hand breaks, meet *Review your work*'s done condition, step 4's exemptions aside, each agreed GitHub setting in place, by the API or whoever decides, and each planned change is open with its process's entries, on its branch, in the reply or waiting on an answer.

**Reply:** the record and each follow-up.
